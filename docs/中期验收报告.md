中期验收报告

课题名称：基于多模态的知识图谱问答系统设计与实现

截至时间：2026年3月26日

一、简述开题以来所做的具体工作和取得的进展或成果

开题以来，本课题围绕“多源知识接入、知识图谱构建、智能问答与图谱可视化”四条主线推进。在不改变研究目标的前提下，结合现有项目基础与个人开发条件，对技术实现路线进行了工程化调整：后端以 Go 为主，前端采用 React 和 TypeScript，底层存储采用 PostgreSQL、Redis、MinIO、Qdrant 与 Neo4j 组合，整体部署方式采用 Docker Compose，以保证系统具备较好的可落地性、扩展性与可维护性。

1. 已完成课题需求梳理、系统总体方案设计与关键技术选型，明确了知识库管理、文档导入、RAG 问答、图谱构建、图谱查询和可视化展示等核心模块。

2. 已完成基础平台搭建与多源知识接入能力建设，当前系统支持 PDF、Word、Markdown、HTML 等文档上传，并支持 URL、RSS、Sitemap 等外部内容导入，实现了知识内容的统一入库与管理。

3. 已完成知识库、文档、目录、用户、系统配置等基础业务模块开发，为后续图谱构建和问答增强提供了稳定的数据基础。

4. 已完成基于 Qdrant 的向量检索与大模型问答基础链路，实现了知识库内容的智能检索、对话问答及历史会话管理，形成了系统的第一阶段可用能力。

5. 已完成 Neo4j 图数据库接入、Schema 初始化及 PostgreSQL 向 Neo4j 的迁移工具开发，初步构建了 Document、Folder、KnowledgeBase、User 等图谱节点，以及 CONTAINS、BELONGS_TO、CREATED_BY、EDITED_BY、RELATED_BY_KEYWORD 等关系模型。

6. 已完成图谱同步机制设计与实现。当前文档、文件夹、用户、知识库的新增、更新、删除、移动等操作均可触发图谱同步，并引入了“自动重试 + 指数退避 + 死信落库 + 手动重放”的补偿机制，提高了图谱数据最终一致性与故障恢复能力。

7. 已完成文档关系自动构建的初步实现。当前采用“标题加权 + 正文 token 提取 + 中文 bi-gram + 英文词项切分 + Jaccard 相似度”的方法，自动生成文档之间的关联关系，为后续实体关系构建和图谱问答提供了基础。

8. 已完成后台图谱管理与可视化原型开发，新增 /graph 页面，支持图谱统计、全图浏览、节点关系查询，以及 2D 和 3D 两种展示方式，具备节点聚焦、缩放、预览等交互能力。

9. 已完成部分代码验证工作。图谱 tokenizer 相关测试与领域模型相关测试能够通过，说明部分核心逻辑已具备基本正确性。

总体来看，截至2026年3月26日，课题已完成中期阶段的基础架构搭建、核心数据链路打通和图谱原型实现，系统已从“方案设计”进入“可运行原型与重点功能完善”阶段。

二、存在的具体问题

1. 与开题报告提出的“多模态”目标相比，目前已完成的内容仍以文本和文档类数据为主，截图、图片 OCR、聊天记录解析等模块尚未实现，多模态接入能力仍不完整。

2. 当前知识图谱已完成文档、文件夹、用户、知识库等基础对象建模，但面向实体的自动抽取与关系抽取尚未完全闭环。Entity 节点模型和检索接口已预留，但实体识别、实体消歧、MENTIONS 与 RELATES_TO 等关系生成仍需继续开发。

3. 图谱问答能力尚处于过渡阶段。目前系统已经具备 RAG 问答和图谱查询接口，但“自然语言问题到 Cypher 查询，再到图谱结果生成答案”的完整链路尚未完全打通，多跳推理能力仍需完善。

4. 图谱质量仍受限于当前关系构建方法。基于关键词和相似度的文档关联算法具有实现简单、可解释性强的优点，但语义理解能力有限，对复杂关系和隐式关系的表达能力仍然不足。

5. 系统联调和性能测试仍不充分。由于项目涉及数据库、消息队列、向量库、图数据库等多个组件，完整场景下的稳定性、响应时间与资源消耗还需要进一步评估。

6. 论文实验指标和阶段性量化评价体系尚未完全形成，后续仍需补充图谱覆盖率、问答效果、响应时间等实验数据，增强论文论证的完整性。
