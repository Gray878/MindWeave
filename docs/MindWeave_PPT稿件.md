# 绪论
一、背景
1. 企业知识资产快速积累，文档来源分散、形态多样
2. 传统知识库仅支持关键词检索，语义理解能力不足
3. 大语言模型普及，用户对自然语言问答与可解释回答需求显著提升

二、现状
1. 国外：RAG 与知识图谱融合研究逐步成熟，但系统复杂、部署成本高
2. 国内：垂直领域知识图谱应用广泛，但多模态接入能力仍有不足
3. 现有系统普遍缺少知识治理、权限感知、图谱增强的一体化设计

三、研究意义
1. 工程实践价值：覆盖知识接入、治理、发布、问答、图谱的完整闭环
2. 应用推广价值：适用于团队知识沉淀、产品文档服务、FAQ 构建等场景
3. 研究延展价值：为后续 GraphRAG 与智能体接入奠定工程基础

# 系统需求分析
一、系统建设目标
1. 统一知识治理边界：以知识库为核心管理文档的接入、整理与发布
2. 提供稳定的 RAG 检索能力：以发布快照为索引对象，支撑语义检索与智能问答
3. 支持多渠道复用：通过门户、Widget、开放接口与机器人对外提供知识能力

二、核心功能需求
1. 知识库管理：创建、配置、成员管理、访问控制
2. 多源知识接入：本地文件、URL、RSS、Sitemap 等来源
3. 文档发布与版本快照：隔离编辑态与服务态，保证问答依据可追溯
4. AI 问答：SSE 流式输出与证据回显，支持多轮会话与反馈闭环
5. 知识图谱建模与可视化：2D/3D 图谱展示，支持同步补偿与死信恢复

# 系统总体设计
一、总体架构
[系统总体架构图]
前端展示层：React/Vite 管理端 + Next.js 公开门户端
应用服务层：Go + Echo 后端 API
异步处理层：NATS 消息队列 + Consumer 消费者
基础设施层：PostgreSQL、Redis、MinIO、Qdrant、Neo4j

二、关键流程
RAG 问答流程：
文档发布 → 切片 → 向量化 → 写入 Qdrant 索引
用户提问 → 问题改写 → 向量检索召回（TopK=10）→ 重排序过滤 → 组装 Prompt → 大模型流式生成 → SSE 回传证据片段与答案

知识图谱构建流程：
文档发布 → 提取实体与关系 → 异步同步至 Neo4j → 失败则重试/写死信表 → 管理员手动重放

# 系统功能实现
一、AI 智能问答
[AI 问答链路示意图]
1. dataset_id 划定知识边界，召回相关证据片段
2. SSE 先回传证据片段，再回传模型生成内容
3. 支持多轮会话与反馈闭环

三、核心数据模型设计
[数据模型协同示意图]
系统数据模型由关系型主数据模型、向量检索模型和图谱模型组成，各部分围绕知识库边界协同工作。

关系型主数据模型：
知识库、成员关系、节点、发布快照、会话消息、评论反馈、统计记录、图谱死信

向量检索模型：
以发布快照为索引对象，每个知识库独立 dataset_id，文档切片关联 doc_id 与 group_ids

图谱模型：
节点：KnowledgeBase、Folder、Document、User
关系：CONTAINS、BELONGS_TO、CREATED_BY、RELATED_BY_KEYWORD

# 总结与展望
一、全文总结
1. 构建了覆盖知识接入、治理、发布、问答、图谱与开放接入的完整知识服务平台
