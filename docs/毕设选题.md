## 基于多模态的知识图谱问答系统设计与实现

个人场景无需复杂的分布式架构，核心分为 **4 个模块**，可基于开源工具快速搭建：

| 模块                   | 功能                                                         | 个人友好型工具 / 技术                                        |
| ---------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **知识采集与录入**     | 收集个人信息（笔记、文档、截图、聊天记录），抽取实体和关系   | 1. 手动录入：Excel/Markdown 表格（定义实体、关系）2. 半自动抽取：使用轻量工具（如 jieba 分词 + spaCy）从 Markdown/Word 文档中抽取实体 |
| **知识图谱构建与存储** | 定义 schema（实体类型、关系类型），将采集的信息转化为三元组，并存储 | 1. 图数据库（轻量）：**Neo4j Desktop**（可视化界面，适合个人）、**Dgraph**（易部署）2. 轻量化替代：SQLite（用两张表存储实体和关系，适合技术小白） |
| **问答交互模块**       | 接收自然语言问题，解析为查询意图，转化为图查询语句           | 1. 基础版：基于**关键词 + 规则匹配**（适合个人小数据量，无需复杂 NLP 模型）2. 进阶版：使用开源轻量模型（如 BERT-tiny、ChatGLM-6B 量化版）做语义解析 |
| **答案生成与展示**     | 执行查询语句，从知识图谱中获取结果，转化为自然语言答案并展示 | 1. 命令行 / 简单 GUI（如 PyQt 制作桌面端）2. 网页端：**Streamlit**（快速搭建可视化问答界面，Python 代码即可） |



## 项目意义

项目突破传统知识图谱静态构建局限，通过自动化多模态数据摄入管道，让普通用户轻松拥有个性化“知识网络”，解决个人笔记碎片化、手动标注成本高、图谱难维护三大痛点，具有个人知识管理、学术研究、团队协作等广泛应用价值，推动图数据库在日常场景落地。

## 主要内容及要求

系统包含数据上传预处理、实体关系抽取、Neo4j图谱构建、智能问答及可视化四大模块。主要技术栈为Python（spaCy/BERT抽取、Py2neo操作Neo4j）、Flask/Django后端、ECharts前端图可视化，要求支持笔记/PDF/截图/聊天记录多格式上传，实现增量三元组提取和多跳推理问答，并提供Web管理界面。

## 毕业设计（论文）的内容要求

（1）实现多模态数据的采集与录入功能，支持笔记、文档、PDF、截图及聊天记录等多种数据形式的上传与管理；

（2）实现实体与关系的抽取功能，能够从结构化和非结构化数据中提取实体信息及其关系，形成规范的三元组数据；

（3）实现知识图谱的构建与存储功能，设计合理的图谱 Schema，并将抽取的实体与关系数据存储至图数据库中，实现图谱的可视化管理；

（4）实现基于知识图谱的问答交互功能，支持用户通过自然语言方式进行提问，并将问题解析为对应的查询请求；

（5）实现答案生成与展示功能，能够对图数据库查询结果进行处理，并以自然语言形式返回问答结果，同时提供图形化展示界面；

（6）利用数据库对系统相关数据进行统一存储与管理，支持图谱数据及问答结果的查询与维护；

（7）完成系统整体测试与调试，对系统功能完整性和运行稳定性进行验证，确保系统满足毕业设计的各项要求。
