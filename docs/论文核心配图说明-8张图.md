# 毕业论文核心配图说明（扩展版，12 张重点图）

本文档用于配合论文 [毕业论文初稿-基于多模态的知识图谱问答系统设计与实现.md](./毕业论文初稿-基于多模态的知识图谱问答系统设计与实现.md) 出图。目标不是直接画图，而是把每一张图的含义、结构、元素、连线、版式和插入位置描述清楚，方便后续单独交给 AI 或设计工具生成正式插图。

## 使用说明

- 当前版本按论文第 `4.3` 与 `4.4` 的章节结构进行了拆分，共整理 `12` 张重点图。
- `4.3 核心数据模型设计` 不再使用一张综合 ER 图，而是拆成：
  - `图 4-3 关系型主数据模型图`
  - `图 4-4 向量检索数据模型图`
  - `图 4-5 图谱数据模型图`
- `4.4 关键业务流程设计` 按正文 5 个子流程分别配置独立流程图：
  - `图 4-6 知识库创建流程图`
  - `图 4-7 文档导入与发布流程图`
  - `图 4-8 用户问答流程图`
  - `图 4-9 图谱同步与恢复流程图`
  - `图 4-10 多渠道接入流程图`
- 每张图都给出“建议图号”，你可以根据最终排版顺序微调。
- “建议插入位置”尽量写到章节和段落层级，方便你在论文中落位。
- 如果后续交给 AI 画图，优先保留文档中的“图中必须出现的元素”和“连线关系”，不要只保留标题。
- 所有图建议采用统一风格：
  - 统一采用简约黑白的论文图风格，以黑、白、灰为主，不使用彩色强调。
  - 背景保持白底，边框、箭头、连线与分区边界使用黑色或深灰色细线。
  - 如需区分层次，优先使用实线、虚线、浅灰填充和线框粗细变化，不使用渐变、阴影或拟物图标。
  - 箭头方向尽量统一为从左到右或从上到下。
  - 图中文字尽量使用中文，核心技术名保留英文，如 `PostgreSQL`、`Qdrant`、`Neo4j`、`NATS`、`SSE`、`dataset_id`、`group_ids`。

- 建议自上而下分层布局。

## 图 4 向量检索数据模型图

- 建议图号：`图 4-4 向量检索数据模型图`
- 对应章节：`4.3.2 向量检索数据模型`
- 建议插入位置：放在 `4.3.2` 第一段之后。
- 推荐图类型：`数据映射图` 或 `写入-召回双链路图`
- 这张图的作用：
  - 把向量层单独画清楚，避免它淹没在大 ER 图里。
  - 说明 `dataset_id`、`doc_id`、`group_ids` 三个关键元数据如何工作。
  - 直接支撑“权限过滤发生在检索阶段”的设计论证。

### 图中必须出现的元素

- 上游业务对象
  - `knowledge_bases.dataset_id`
  - `node_releases.doc_id`
  - 节点权限组信息
- 索引写入对象
  - `dataset`
  - `chunk`
  - 向量化结果
- 查询输入对象
  - 用户问题 `query`
  - 历史消息 `history`
  - `dataset_id`
  - `group_ids`
- 查询输出对象
  - 候选片段
  - `doc_id` 映射回发布文档
  - 证据组织结果

### 推荐布局

- 推荐画成左右两部分：
  - 左侧：发布写入链路
  - 右侧：问答召回链路
- 左侧从上到下画：
  - `node_releases`
  - 文档切片
  - 向量化
  - `chunk`
  - 写入 `dataset`
- 右侧从上到下画：
  - 用户问题
  - 构造检索请求
  - 基于 `dataset_id + group_ids` 召回
  - 返回候选片段
  - 通过 `doc_id` 映射回发布文档
- 中间可用一个虚线框标注：
  - `受控检索空间`

### 连线关系

- `knowledge_bases.dataset_id` -> `dataset`
- `node_releases.doc_id` -> `chunk.doc_id`
- 节点权限组信息 -> `group_ids`
- 发布后的 `node_releases` -> 文档切片 -> 向量化 -> `chunk`
- 用户问题 + 历史消息 + `dataset_id` + `group_ids` -> 检索请求
- 检索请求 -> 向量召回
- 候选片段 -> `doc_id` 回映发布文档 -> 证据组织

### 图中必须强调的概念

- 向量层的索引对象是 `node_releases`，不是编辑态 `nodes`。
- `dataset_id` 用于划定知识库边界。
- `group_ids` 用于在检索阶段完成权限过滤。
- `doc_id` 负责把召回结果映射回业务文档与引用关系。
- 向量层是服务层，不是事实层。

### 图里建议写出的文字

- 在左侧写入链路旁写：
  - `发布后写入索引`
- 在检索请求构造处写：
  - `query + history + dataset_id + group_ids`
- 在召回模块旁写：
  - `按知识边界与权限元数据受控召回`
- 在映射回业务对象处写：
  - `doc_id 回映发布文档`
