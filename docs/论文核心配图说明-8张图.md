  - PostgreSQL

  - MinIO

  - Neo4j
  - NATS
- `NATS` 再连接 `Consumer`
- `Consumer` 再连接 `Qdrant/Raglite` 与 `Neo4j`

### 时序参与者

- 用户
- 门户端/Widget
- Go/Echo API
- 会话服务/权限校验逻辑
- Raglite/Qdrant 检索层
- 大语言模型服务
- PostgreSQL

### 时序步骤

1. 用户提交问题
2. 门户端/Widget 调用问答接口
3. API 校验知识库状态、入口合法性、公开访问条件
4. API 建立新会话或续接会话
5. API 根据 `dataset_id`、`group_ids`、问题和历史消息构造检索请求
6. 检索层召回候选片段
7. API 对候选证据进行裁剪、排序、组织
8. API 先把证据块通过 SSE 回传给前端
9. API 拼装提示词并请求大模型生成回答
10. 大模型返回流式文本
11. API 通过 SSE 持续回传答案
12. API 将消息、引用关系、反馈状态写入 PostgreSQL
13. 前端展示最终回答

### 推荐布局

- 标准时序图，从左到右放各参与者。
- 用户和前端在最左侧。
- API 在中间。
- 检索层和模型服务在右侧。
- PostgreSQL 放最右侧或右下侧。

### 必须突出显示的关键点

- 检索时使用：
  - `dataset_id` 限定知识库边界
  - `group_ids` 执行权限过滤
- 回答前：
  - 先回传证据块
  - 后回传答案文本
- 持久化时：
  - 保存会话
  - 保存消息
