## 二、核心缺失功能 (需要开发)

### 1. 实体关系抽取模块 ❌ (0% 完成)

**需要实现的功能:**

#### 1.1 实体识别 (NER)
- 命名实体识别: 人名、地名、机构名、时间等
- 自定义实体类型
- 实体消歧

**技术方案:**
```
方案 A: 调用 Python NLP 库 (推荐)
- 使用 spaCy/BERT 做实体识别
- Go 通过 HTTP API 或 gRPC 调用 Python 服务
- 优点: 成熟的 NLP 工具链
- 缺点: 需要额外的 Python 服务

方案 B: 使用 Go NLP 库
- prose (Go 原生 NLP 库)
- 优点: 纯 Go 实现，部署简单
- 缺点: 功能相对简单，准确率较低

方案 C: 调用第三方 API
- 百度 NLP、腾讯 NLP、阿里 NLP
- 优点: 开箱即用
- 缺点: 需要付费，依赖外部服务
```

**推荐实现路径:**
1. 创建 `backend/pkg/nlp/` 模块
2. 实现 `EntityExtractor` 接口
3. 支持多种实体识别后端 (Python/API)

#### 1.2 关系抽取
- 实体间关系识别
- 关系类型定义
- 三元组生成 (主语-谓语-宾语)

**技术方案:**
```
方案 A: 基于规则的关系抽取
- 依存句法分析
- 模式匹配
- 优点: 可控性强
- 缺点: 覆盖率有限

方案 B: 基于深度学习的关系抽取
- BERT + 关系分类
- 优点: 准确率高
- 缺点: 需要训练数据

方案 C: 混合方案 (推荐)
- 规则 + 模型结合
- 先用规则提取明确关系
- 再用模型补充复杂关系
```

**代码结构:**
```go
// backend/pkg/nlp/extractor.go
type Entity struct {
    ID    string
    Text  string
    Type  string
    Start int
    End   int
}

type Relation struct {
    Subject   Entity
    Predicate string
    Object    Entity
    Confidence float64
}

type Triple struct {
    Subject   string
    Predicate string
    Object    string
}

type Extractor interface {
    ExtractEntities(text string) ([]Entity, error)
    ExtractRelations(text string, entities []Entity) ([]Relation, error)
    ExtractTriples(text string) ([]Triple, error)
}
```

```go
// 1. 添加 Neo4j 依赖
// go.mod
require github.com/neo4j/neo4j-go-driver/v5 v5.x.x

// 2. 创建 Neo4j 存储层
// backend/store/graph/neo4j.go
type Neo4jStore struct {
    driver neo4j.DriverWithContext
    logger *log.Logger
}

func NewNeo4jStore(uri, username, password string) (*Neo4jStore, error) {
    driver, err := neo4j.NewDriverWithContext(uri, neo4j.BasicAuth(username, password, ""))
    if err != nil {
        return nil, err
    }
    return &Neo4jStore{driver: driver}, nil
}

// 3. 实现图谱操作接口
type GraphStore interface {
    CreateNode(ctx context.Context, node *Node) error
    CreateRelation(ctx context.Context, rel *Relation) error
    QueryByEntity(ctx context.Context, entityID string) ([]Node, []Relation, error)
    QueryByPattern(ctx context.Context, pattern string) ([]Path, error)
}
```

### 3. 基于图谱的问答 ❌ (30% 完成)

**需要实现的功能:**

#### 3.1 自然语言转 Cypher
- 问题意图识别
- 实体链接
- Cypher 查询生成

**实现方案:**
```
方案 A: 基于模板的转换
- 预定义问题模板
- 模板匹配 + 参数填充
- 优点: 简单可控
- 缺点: 覆盖有限

方案 B: 基于 LLM 的转换 (推荐)
- 使用 LLM (GPT/Claude) 生成 Cypher
- Few-shot learning
- 优点: 灵活性强
- 缺点: 需要 prompt 工程

方案 C: 混合方案
- 简单问题用模板
- 复杂问题用 LLM
```

**代码示例:**
```go
// backend/usecase/graph_qa.go
type GraphQAUsecase struct {
    graphStore *graph.Neo4jStore
    llmUsecase *LLMUsecase
    nlpExtractor nlp.Extractor
}

func (u *GraphQAUsecase) Answer(ctx context.Context, question string) (string, error) {
    // 1. 提取问题中的实体
    entities, _ := u.nlpExtractor.ExtractEntities(question)
    
    // 2. 生成 Cypher 查询
    cypher, _ := u.generateCypher(question, entities)
    
    // 3. 执行图谱查询
    results, _ := u.graphStore.Query(ctx, cypher)
    
    // 4. 结果转自然语言
    answer, _ := u.generateAnswer(question, results)
    
    return answer, nil
}
```

## 五、技术难点与解决方案

### 难点 1: 实体关系抽取准确率
**解决方案:**
- 使用预训练模型 (BERT)
- 针对特定领域微调
- 人工标注 + 主动学习

### 难点 2: 自然语言转 Cypher
**解决方案:**
- 使用 LLM (GPT-4) 生成
- 构建 Few-shot 示例库
- 查询结果验证与修正

### 难点 3: 图谱可视化性能
**解决方案:**
- 分页加载节点
- 只展示核心子图
- 使用 WebGL 渲染

### 难点 4: 实体消歧与合并
**解决方案:**
- 实体链接算法
- 相似度计算
- 人工审核机制

## 六、最终结论

**PandaWiki 可以作为毕设基础项目，但需要补充以下核心模块:**

1. ✅ 可以直接使用的部分 (60%):
   - 数据采集框架
   - Web 界面框架
   - 用户管理
   - 文档管理
   - 基础问答能力

2. ❌ 需要新增的部分 (40%):
   - 实体关系抽取 (核心)
   - Neo4j 图谱存储 (核心)
   - 图谱问答 (核心)
   - 图谱可视化 (重要)

**工作量合理性:**
- 利用现有框架可节省 50-60% 开发时间
