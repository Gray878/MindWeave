# 知识图谱实体关系设计

## 一、核心实体 (Neo4j Node Labels)

基于 PandaWiki 数据库表结构分析，设计以下实体类型：

### 1. Document (文档)
来源表: `nodes` (type=1, 文档类型)

属性:
- id: string (主键)
- name: string (文档标题)
- content: string (文档内容，用于实体抽取)
- kb_id: string (所属知识库)
- status: int (状态: 1=正常)
- visibility: int (可见性)
- creator_id: string (创建者)
- editor_id: string (编辑者)
- created_at: timestamp
- updated_at: timestamp
- edit_time: timestamp

用途: 知识图谱的核心载体，从文档内容中抽取实体和关系

### 2. Folder (文件夹)
来源表: `nodes` (type=0, 文件夹类型)

属性:
- id: string
- name: string (文件夹名称)
- kb_id: string
- parent_id: string (父文件夹)
- position: float (排序位置)
- created_at: timestamp

用途: 组织文档结构，可作为知识分类的参考

### 3. Entity (实体)
来源: AI 抽取 (从 Document.content 中提取)

属性:
- id: string (自动生成)
- name: string (实体名称，如"张三"、"Python")
- type: string (实体类型，如 Person、Technology、Concept)
- aliases: string[] (别名列表)
- description: string (实体描述)
- confidence: float (置信度 0-1)
- source_doc_ids: string[] (来源文档 ID 列表)
- created_at: timestamp
- updated_at: timestamp

实体类型枚举:
- Person (人物)
- Organization (组织/公司)
- Technology (技术/工具)
- Concept (概念/术语)
- Product (产品)
- Event (事件)
- Location (地点)
- Other (其他)

### 4. User (用户)
来源表: `users`

属性:
- id: string
- account: string (账号)
- role: string (角色: admin/user)
- created_at: timestamp

用途: 关联文档创建者、编辑者

### 5. KnowledgeBase (知识库)
来源表: `knowledge_bases`

属性:
- id: string
- name: string (知识库名称)
- created_at: timestamp

用途: 隔离不同知识库的图谱数据

## 二、核心关系 (Neo4j Relationships)

### 1. CONTAINS (包含关系)
方向: Folder -> Document
方向: Folder -> Folder

属性:
- position: float (排序位置)
- created_at: timestamp

用途: 表示文件夹包含文档或子文件夹

### 2. MENTIONS (提及关系)
方向: Document -> Entity

属性:
- count: int (提及次数)
- positions: int[] (在文档中的位置)
- context: string[] (上下文片段)
- confidence: float (置信度)
- created_at: timestamp

用途: 表示文档中提及了某个实体

### 3. RELATES_TO (实体关联)
方向: Entity -> Entity

属性:
- relation_type: string (关系类型)
- description: string (关系描述)
- confidence: float (置信度)
- source_doc_ids: string[] (关系来源文档)
- created_at: timestamp

关系类型枚举:
- DEPENDS_ON (依赖)
- SIMILAR_TO (相似)
- PART_OF (属于)
- USES (使用)
- IMPLEMENTS (实现)
- EXTENDS (扩展)
- RELATED_TO (相关)

### 4. CREATED_BY (创建关系)
方向: Document -> User

属性:
- created_at: timestamp

用途: 表示文档的创建者

### 5. EDITED_BY (编辑关系)
方向: Document -> User

属性:
- edit_time: timestamp

用途: 表示文档的最后编辑者

### 6. BELONGS_TO (归属关系)
方向: Document -> KnowledgeBase
方向: Entity -> KnowledgeBase

属性:
- created_at: timestamp

用途: 表示文档或实体属于某个知识库

### 7. REFERENCES (引用关系)
方向: Document -> Document

属性:
- reference_type: string (引用类型: link/quote/related)
- created_at: timestamp

用途: 表示文档之间的引用关系 (可从文档内链接中提取)

## 三、图谱数据模型示例

```cypher
// 示例 1: 文档提及实体
(:Document {id: "doc1", name: "Python 入门教程"})
  -[:MENTIONS {count: 5, confidence: 0.95}]->
(:Entity {id: "e1", name: "Python", type: "Technology"})

// 示例 2: 实体之间的关系
(:Entity {name: "Django", type: "Technology"})
  -[:RELATES_TO {relation_type: "DEPENDS_ON", confidence: 0.9}]->
(:Entity {name: "Python", type: "Technology"})

// 示例 3: 文档结构
(:Folder {name: "技术文档"})
  -[:CONTAINS {position: 1.0}]->
(:Document {name: "Python 入门"})
  -[:CREATED_BY]->
(:User {account: "admin"})

// 示例 4: 文档引用
(:Document {name: "Django 教程"})
  -[:REFERENCES {reference_type: "link"}]->
(:Document {name: "Python 入门"})
```

## 四、数据迁移策略

### 阶段 1: 基础结构迁移 (PostgreSQL -> Neo4j)

1. 迁移 KnowledgeBase
   - 从 `knowledge_bases` 表读取
   - 创建 Neo4j KnowledgeBase 节点

2. 迁移 User
   - 从 `users` 表读取
   - 创建 Neo4j User 节点

3. 迁移 Folder 和 Document
   - 从 `nodes` 表读取 (按 type 区分)
   - 创建 Neo4j Folder/Document 节点
   - 根据 parent_id 创建 CONTAINS 关系
   - 根据 creator_id/editor_id 创建 CREATED_BY/EDITED_BY 关系

### 阶段 2: 实体抽取 (AI 处理)

1. 遍历所有 Document 节点
2. 使用 NLP 模型从 content 中抽取实体
3. 创建 Entity 节点
4. 创建 MENTIONS 关系

### 阶段 3: 关系抽取 (AI 处理)

1. 分析实体共现模式
2. 使用关系抽取模型识别实体间关系
3. 创建 RELATES_TO 关系

### 阶段 4: 文档引用分析

1. 解析文档内容中的内部链接
2. 创建 REFERENCES 关系

## 五、Neo4j Schema 定义

```cypher
// 创建约束 (确保 ID 唯一)
CREATE CONSTRAINT document_id IF NOT EXISTS FOR (d:Document) REQUIRE d.id IS UNIQUE;
CREATE CONSTRAINT folder_id IF NOT EXISTS FOR (f:Folder) REQUIRE f.id IS UNIQUE;
CREATE CONSTRAINT entity_id IF NOT EXISTS FOR (e:Entity) REQUIRE e.id IS UNIQUE;
CREATE CONSTRAINT user_id IF NOT EXISTS FOR (u:User) REQUIRE u.id IS UNIQUE;
CREATE CONSTRAINT kb_id IF NOT EXISTS FOR (k:KnowledgeBase) REQUIRE k.id IS UNIQUE;

// 创建索引 (提升查询性能)
CREATE INDEX document_name IF NOT EXISTS FOR (d:Document) ON (d.name);
CREATE INDEX entity_name IF NOT EXISTS FOR (e:Entity) ON (e.name);
CREATE INDEX entity_type IF NOT EXISTS FOR (e:Entity) ON (e.type);
CREATE INDEX document_kb IF NOT EXISTS FOR (d:Document) ON (d.kb_id);
```

## 六、查询示例

### 查询 1: 查找文档中提及的所有实体
```cypher
MATCH (d:Document {id: $docId})-[m:MENTIONS]->(e:Entity)
RETURN e.name, e.type, m.count, m.confidence
ORDER BY m.count DESC
```

### 查询 2: 查找与某实体相关的所有文档
```cypher
MATCH (d:Document)-[m:MENTIONS]->(e:Entity {name: $entityName})
RETURN d.id, d.name, m.count
ORDER BY m.count DESC
LIMIT 10
```

### 查询 3: 查找实体的关联实体 (2 跳)
```cypher
MATCH (e1:Entity {name: $entityName})-[r:RELATES_TO*1..2]-(e2:Entity)
RETURN DISTINCT e2.name, e2.type, r
LIMIT 20
```

### 查询 4: 查找文档的知识网络 (文档 + 实体 + 关联)
```cypher
MATCH (d:Document {id: $docId})-[:MENTIONS]->(e1:Entity)
OPTIONAL MATCH (e1)-[r:RELATES_TO]-(e2:Entity)
RETURN d, e1, r, e2
```

### 查询 5: 查找某知识库的实体统计
```cypher
MATCH (e:Entity)-[:BELONGS_TO]->(kb:KnowledgeBase {id: $kbId})
RETURN e.type, count(e) as count
ORDER BY count DESC
```

## 七、图谱质量指标

### 1. 覆盖率指标
- 文档覆盖率: 有实体的文档数 / 总文档数
- 实体密度: 总实体数 / 总文档数
- 关系密度: 总关系数 / 总实体数

### 2. 质量指标
- 平均置信度: AVG(Entity.confidence)
- 孤立实体率: 无关系的实体数 / 总实体数
- 实体去重率: 合并的重复实体数 / 原始实体数

### 3. 活跃度指标
- 热门实体: 被提及次数最多的实体 TOP 10
- 核心文档: 包含实体最多的文档 TOP 10
- 关键关系: 连接实体最多的关系类型
