### 2.3 核心代码修改点

#### 修改 1: 数据类型定义

**GitNexus 的数据结构** (KuzuDB):

**PandaWiki 需要的数据结构** (Neo4j):
```typescript

interface Neo4jNode {
  identity: string;  // Neo4j 节点 ID

    name: string;
```

**原始 GitNexus 函数**:

**修改后的 PandaWiki 函数**:
```typescript
export const neo4jToGraphology = (
  data: KnowledgeGraphData
): Graph<SigmaNodeAttributes, SigmaEdgeAttributes> => {
  const graph = new Graph<SigmaNodeAttributes, SigmaEdgeAttributes>();
  
  // 添加节点
  data.nodes.forEach((node) => {
    const nodeType = node.labels[0] || 'Unknown';
    const color = getNodeColor(nodeType);
    const size = getNodeSize(nodeType);
    
    graph.addNode(node.identity, {
      x: Math.random() * 1000 - 500,  // 初始随机位置
      y: Math.random() * 1000 - 500,
      size,
      color,
      label: node.properties.name || node.identity,
      nodeType,
      properties: node.properties,
      hidden: false,
    });
  });
  
  // 添加边
  data.relationships.forEach((rel) => {
    if (graph.hasNode(rel.start) && graph.hasNode(rel.end)) {
      graph.addEdge(rel.start, rel.end, {
        size: 1,
        color: getEdgeColor(rel.type),
        relationType: rel.type,
        type: 'curved',
        curvature: 0.15,
      });
    }
  });
  
  return graph;
};
```

### 4.2 Neo4j 查询示例

#### 查询 1: 获取所有节点和关系

```cypher
// 获取所有节点 (限制数量)
MATCH (n)
RETURN n
LIMIT 10000

// 获取所有关系
MATCH (n)-[r]->(m)
RETURN n, r, m
LIMIT 10000
```

#### 查询 2: 获取文档相关实体

```cypher
// 假设文档和实体通过 MENTIONS 关系连接
MATCH (doc:Document {id: $docId})-[:MENTIONS]->(entity)
OPTIONAL MATCH (entity)-[r]-(related)
RETURN entity, r, related
LIMIT 100
```

#### 查询 3: 获取 N 跳邻居

```cypher
// 获取 2 跳内的所有邻居
MATCH path = (center {id: $entityId})-[*1..2]-(neighbor)
WITH nodes(path) as pathNodes, relationships(path) as pathRels
UNWIND pathNodes as n
UNWIND pathRels as r
RETURN DISTINCT n, r
LIMIT 500
```

```typescript
// 分页加载节点
const loadGraphInChunks = async (chunkSize = 1000) => {
  let offset = 0;
  let hasMore = true;
  
  while (hasMore) {
    const chunk = await fetchGraphChunk(offset, chunkSize);
    addNodesToGraph(chunk);
    offset += chunkSize;
    hasMore = chunk.nodes.length === chunkSize;
  }
};
```

```typescript
const highlightNeighbors = (nodeId: string) => {
  const neighbors = graph.neighbors(nodeId);
  
  graph.forEachNode((node) => {
    if (node === nodeId || neighbors.includes(node)) {
      graph.setNodeAttribute(node, 'highlighted', true);
```

### 6.3 数据同步

#### 实时更新

```typescript
// 使用 WebSocket 或轮询
const subscribeToGraphUpdates = () => {
  const ws = new WebSocket('ws://localhost/api/graph/updates');
  
  ws.onmessage = (event) => {
    const update = JSON.parse(event.data);
    
    if (update.type === 'node_added') {
      addNodeToGraph(update.node);
    } else if (update.type === 'node_updated') {
      updateNodeInGraph(update.node);
    } else if (update.type === 'node_deleted') {
      removeNodeFromGraph(update.nodeId);
    }
    
    sigma.refresh();
  };
};
```

## 七、注意事项

### 7.1 GitNexus 特定功能 (不需要复制)

以下功能是 GitNexus 特有的,PandaWiki 不需要:

1. **KuzuDB WASM**: GitNexus 使用浏览器内图数据库,PandaWiki 使用服务端 Neo4j
2. **代码解析**: GitNexus 解析代码文件,PandaWiki 处理文档实体
3. **社区检测**: GitNexus 使用 Leiden 算法,PandaWiki 可选
4. **AI 问答集成**: GitNexus 的 LangChain 集成,PandaWiki 已有自己的问答系统

### 7.2 需要保留的核心功能

1. **Sigma.js 渲染**: 完整保留
2. **ForceAtlas2 布局**: 完整保留
3. **节点交互**: 点击、悬停、选中
4. **缩放和平移**: 完整保留
5. **过滤功能**: 按节点类型过滤

### 7.3 需要修改的部分

1. **数据类型**: KuzuDB → Neo4j
2. **节点颜色**: 代码节点 → 知识实体
3. **关系类型**: 代码关系 → 知识关系
4. **API 接口**: 本地 WASM → 服务端 API

## 九、总结

通过复用 GitNexus 的核心可视化组件,可以快速实现 PandaWiki 的知识图谱功能:

1. **复用度高**: 80% 的可视化代码可以直接复用
2. **修改量小**: 主要修改数据适配器和颜色配置
3. **技术成熟**: Sigma.js 是业界标准的图可视化库
4. **性能优秀**: WebGL 渲染 + Web Worker 布局
5. **工作量可控**: 核心功能 4-5 周可完成

关键是要理解 GitNexus 的数据流:
```
KuzuDB → KnowledgeGraph → Graphology → Sigma.js
```

修改为 PandaWiki 的数据流:
```
Neo4j → KnowledgeGraphData → Graphology → Sigma.js
```

只需要修改第一步的数据适配,后续的可视化逻辑完全复用。
